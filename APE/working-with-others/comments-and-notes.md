# Comments and notes

Two different conversations happen around a prototype: feedback about what's on screen, and coordination between people. They work differently.

## Comments[​](#comments "Direct link to Comments")

Feedback attached to a specific element, on a specific route.

Turn on **Comment** in the floating toolbar, click the element you want to talk about, and write. The comment is saved along with a screenshot of exactly what you were looking at.

That screenshot is the point. Three days later, after the prototype has moved on, the comment still shows what the person was reacting to.

### Threads[​](#threads "Direct link to Threads")

Comments are threads. Reply to continue a conversation; `@mention` someone to pull them in.

Open the comments panel to see all of them, filtered by **Open**, **Resolved**, or **All**. Click a thread to open it; if it's on a different route, opening it takes you there.

The panel floats over the preview and you can drag it out of the way.

### Resolving[​](#resolving "Direct link to Resolving")

Resolve a thread when it's dealt with. Resolved threads stay in the list under the Resolved filter and can be reopened.

### Reviewers don't need edit access[​](#reviewers-dont-need-edit-access "Direct link to Reviewers don't need edit access")

Comments work in read-only view. Someone with just a share link can leave anchored, screenshotted feedback without being added to anything, and without having used APE before.

That's the intended review loop: send the link, collect comments, work through them.

## Notes[​](#notes "Direct link to Notes")

A message to a person, in the chat, that doesn't go to the agent.

Start your message with `@` and their name. The composer turns amber to confirm, and the message posts as a note – no agent run, no queue.

> @jonas I've left the checkout flow half-done, can you pick up the payment step?

Notes appear in the same thread as the prompts and the agent's work, so context stays together. Someone reading the session later sees the decisions alongside the changes that came from them.

You can send a note while the agent is mid-run. It won't interrupt anything.

## Which to use[​](#which-to-use "Direct link to Which to use")

|                              | Comment                      | Note                           |
| ---------------------------- | ---------------------------- | ------------------------------ |
| Attached to                  | An element on a route        | The session                    |
| Includes a screenshot        | Yes                          | No                             |
| Visible to read-only viewers | Yes, and they can write them | They can read them             |
| Starts an agent run          | No                           | No                             |
| Good for                     | "This spacing is wrong"      | "I'm handing this over to you" |

Rough rule: if you're pointing at something, comment. If you're talking to someone, note.
